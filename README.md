# MAX Bot для онлайн-записи (SaaS-платформа)

Универсальная SaaS-платформа для онлайн-записи через мессенджер **MAX**. Поддерживает несколько независимых заведений (мультитенантность): клиент выбирает организацию, услугу, специалиста и время, после чего запись создаётся в 1С соответствующего заведения.

Платформа подходит для **любого бизнеса с записью по времени**:

- 💇 Парикмахерские и салоны красоты
- 🏥 Клиники и стоматологии
- 🚗 Автосервисы и СТО
- 💆 Массажные и косметологические кабинеты
- 🐕 Груминг и ветеринарные клиники
- 📚 Репетиторы и консультанты
- 🏋️ Тренеры и фитнес-инструкторы

В качестве примера в проекте настроены **две парикмахерские**, но тип заведения — параметр, который можно изменить одной строкой в базе.

## Назначение

**Платформа онлайн-записи для бизнеса по подписке.** Каждое заведение (тенант) получает:

- Свою базу 1С для хранения специалистов и записей.
- Публикацию HTTP-сервиса на Apache.
- Свою карточку в боте MAX — с названием, адресом, телефоном.
- Возможность работать с любым типом услуг: консультации, процедуры, ремонт, приём.

Клиенты через бота MAX:

- Выбирают заведение.
- Смотрят свободные слоты.
- Записываются к конкретному специалисту на конкретное время.
- Получают напоминание за час до визита.

---

## Основной пользовательский сценарий

1. Пользователь пишет боту `/start` в MAX.
2. Бот показывает главное меню.
3. Пользователь нажимает **«🏢 Выбрать заведение»** и выбирает организацию из списка.
4. Нажимает **«✍️ Записаться»**.
5. Выбирает дату в календаре (кнопками, листает недели стрелками `◀️`/`▶️`).
6. Выбирает специалиста из списка (кнопками).
7. Выбирает свободное время (кнопками).
8. Вводит имя и телефон.
9. Бот создаёт запись в 1С выбранного заведения.
10. Пользователь получает подтверждение и напоминание о том, что за час до визита придёт уведомление.
11. За час до визита бот автоматически отправляет напоминание.

## Состав и архитектура решения

```
┌─────────────────────────────────────────────────────────┐
│                  MAX Bot (FastAPI)                       │
│  - Приём вебхуков от MAX                                 │
│  - Логика выбора тенанта                                 │
│  - Календарь, inline-меню, кнопки                        │
│  - Расчёт свободных слотов                               │
│  - Планировщик напоминаний (APScheduler)                 │
└─────────────┬───────────────────────────────────────────┘
              │
              ├─── SQLite (tenants.db) — список подписчиков
              │    + таблица reminders (напоминания)
              ├─── Redis — сессии пользователей (TTL 1 час)
              │
              ├─── 1С #1 (booking1) → заведение A
              └─── 1С #2 (booking2) → заведение B
```

**Компоненты проекта:**

| Файл | Назначение |
|---|---|
| `main.py` | FastAPI, приём вебхуков MAX, логика бота, календарь, меню, планировщик напоминаний |
| `database.py` | Работа с SQLite: тенанты, напоминания |
| `models.py` | Модели `Tenant` и `Reminder` (SQLAlchemy) |
| `Dockerfile` | Сборка образа Python 3.12-slim + сертификаты Минцифры |
| `docker-compose.yml` | Запуск backend + Redis + volume для SQLite |
| `requirements.txt` | Зависимости Python |
| `.env.example` | Пример переменных окружения |
| `data/tenants.db` | SQLite (создаётся автоматически при старте) |

## Внешние сервисы и интеграции

### MAX Bot API

- **Endpoint:** `https://platform-api2.max.ru`
- **Назначение:** приём вебхуков от MAX, отправка сообщений пользователям, напоминаний.
- **Сертификат:** требует корневые сертификаты Минцифры (устанавливаются в `Dockerfile`).

### 1С:Предприятие

- **Публикация:** Apache + модуль расширения веб-сервера 1С (`wsap24.so`).
- **HTTP-сервисы:** `getEmployees`, `records`, `createBooking`, `ping`.
- **Базы:** каждое заведение — отдельная база 1С.
- **Авторизация:** Basic Auth Apache + `Usr`/`Pwd` в `default.vrd`.

### Redis

- **Назначение:** хранение сессий пользователей.
- **TTL:** 1 час.

### SQLite

- **Назначение:** хранение тенантов и напоминаний.
- **Файл:** `/app/data/tenants.db` (volume).

## Работа с данными

### SQLite: таблица `tenants`

| Поле | Описание |
|---|---|
| `id` | Автоинкремент |
| `code` | Уникальный код тенанта (`barber_main`) |
| `name` | Название заведения |
| `type` | Тип (`barbershop`, `clinic`, `autoservice`, ...) |
| `address` | Адрес |
| `phone` | Телефон |
| `onec_url` | URL HTTP-сервиса 1С |
| `onec_user`, `onec_password` | Учётные данные 1С |
| `is_active` | Активна ли подписка |
| `subscription_until` | Дата окончания подписки |

### SQLite: таблица `reminders`

| Поле | Описание |
|---|---|
| `id` | Автоинкремент |
| `user_id` | ID пользователя MAX для отправки напоминания |
| `tenant_code` | Код заведения |
| `employee_name` | Имя специалиста |
| `date`, `time` | Дата и время визита |
| `reminded` | Отправлено ли напоминание |
| `created_at` | Дата создания |

### Redis: ключи

| Ключ | Значение |
|---|---|
| `state:<user_id>` | JSON с состоянием диалога пользователя |

## Добавление нового заведения

**1. Создать базу 1С** для нового заведения (например, `BaseMax2`).

**2. Настроить в базе:**

- Справочник `Сотрудники` — заполнить специалистами.
- Регистр сведений `Записи` — оставить пустым.
- HTTP-сервис `Макс_Запись` с методами `ping`, `getEmployees`, `records`, `createBooking`.

**3. Опубликовать базу на Apache:**

```bash
cd /opt/1cv8/x86_64/8.3.27.2342/
sudo ./webinst -publish -apache24 -wsdir booking3 \
  -dir /var/www/1c/booking3 \
  -connstr "File=/var/1c/BaseMax2;" \
  -confpath /etc/apache2/apache2.conf
sudo systemctl restart apache2
```

**4. Добавить запись в SQLite:**

```bash
sqlite3 /root/max-bot/data/tenants.db
```

```sql
INSERT INTO tenants (code, name, type, address, phone, onec_url, onec_user, onec_password, is_active)
VALUES (
  'clinic_main',
  'Стоматология на Тверской',
  'clinic',
  'г. Москва, ул. Тверская, д. 5',
  '+7 (999) 111-22-33',
  'http://178.21.11.91/booking3/hs/booking',
  'Max',
  '6Cificu',
  1
);
```

**5. Перезапустить бэкенд:**

```bash
cd /root/max-bot
sudo docker compose restart backend
```

**6. Проверить в боте:**

Написать `/start` → **«🏢 Выбрать заведение»** → новое заведение появится в списке.

**Типы заведений** (`type`) — произвольные строки. Можно использовать для группировки или иконок. В текущей версии не влияют на логику, но задел на будущее.

## Порядок работы с тестовыми данными

### 1. Подготовить две базы 1С

- **`BaseMax`** — первое заведение (парикмахерская на Ленина).
- **`BaseMax1`** — второе заведение (парикмахерская в центре).

В каждой базе:

- Справочник `Сотрудники` с заполненными записями.
- Регистр сведений `Записи` (пустой).
- HTTP-сервис `Макс_Запись` с методами `ping`, `getEmployees`, `records`, `createBooking`.

### 2. Опубликовать базы на Apache

```bash
# Первая база
cd /opt/1cv8/x86_64/8.3.27.2342/
sudo ./webinst -publish -apache24 -wsdir booking -dir /var/www/1c/booking \
  -connstr "File=/var/1c/BaseMax;" -confpath /etc/apache2/apache2.conf

# Вторая база
sudo ./webinst -publish -apache24 -wsdir booking2 -dir /var/www/1c/booking2 \
  -connstr "File=/var/1c/BaseMax1;" -confpath /etc/apache2/apache2.conf

sudo systemctl restart apache2
```

### 3. Проверить независимость баз

```bash
curl -u Max:пароль -X POST "http://сервер/booking/hs/booking/getEmployees"
curl -u Max:пароль -X POST "http://сервер/booking2/hs/booking/getEmployees"
```

Специалисты должны быть **разные**.

## Напоминания о записи

**Как работает:**

1. При успешной записи создаётся запись в таблице `reminders` с `reminded = 0`.
2. Планировщик APScheduler **каждые 30 минут** проверяет таблицу.
3. Если до визита меньше **1 часа** и он ещё не прошёл — отправляется напоминание.
4. После отправки флаг `reminded` меняется на `1`.

**Настройка:**

- Интервал проверки: в `main.py` → `scheduler.add_job(check_reminders, "interval", minutes=30)`.
- Окно напоминания: в `check_reminders` → `soon = now + timedelta(hours=1)`.

**Тестовые эндпоинты:**

```bash
# Отправить тестовое сообщение конкретному пользователю
curl -X POST "http://localhost:8000/test-reminder?user_id=121690414"

# Принудительно разослать все ненапомненные записи
curl -X POST "http://localhost:8000/test-force-reminders"
```

**Для production** тестовые эндпоинты можно удалить или закрыть авторизацией.

## Известные ограничения

- **Оплата подписки** — не автоматизирована. Тенанты добавляются вручную в SQLite.
- **HTTPS** — в текущей версии используется xTunnel для тестирования. Для production нужен Nginx + Let's Encrypt.
- **MAX не поддерживает встроенные платежи** — нужна внешняя платёжная система или ручное подтверждение.
- **Тип заведения** (`type`) — не влияет на логику, но задел на будущее (разные сценарии для клиник, автосервисов).
- **`records` в 1С** — параметры передаются в query-параметрах URL, даже при POST.
- **`getEmployees` в 1С** — вызывается через POST, без тела.
- **Планировщик напоминаний** — работает в одном процессе с FastAPI. При масштабировании на несколько инстансов нужен отдельный worker (Celery + Beat).

## Расширение под другие типы заведений

Платформа **универсальна**. Чтобы адаптировать её под клинику или автосервис, достаточно:

1. **Создать новую базу 1С** с той же структурой (Сотрудники, Записи).
2. **Опубликовать** её по новому URL (`/booking3`, `/booking4`, ...).
3. **Добавить запись в SQLite** с нужным `type`:
   ```sql
   INSERT INTO tenants (code, name, type, address, phone, onec_url, onec_user, onec_password, is_active)
   VALUES ('clinic_main', 'Стоматология', 'clinic', '...', '...', 'http://.../booking3/hs/booking', 'Max', '...', 1);
   ```
4. **Перезапустить backend** — новое заведение появится в боте.

**Бизнес-логика бота одинакова для всех типов** — различается только набор специалистов и услуг внутри базы 1С.
