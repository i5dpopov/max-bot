# MAX Bot для записи в различные заведения

Чат-бот в мессенджере **MAX** для онлайн-записи (на примере парикмахерских). Поддерживает несколько заведений (мультитенантность): пользователь выбирает парикмахерскую, дату, сотрудника и время, после чего запись создаётся в базе 1С соответствующего заведения.

## Назначение

Сервис по подписке для парикмахерских. Каждое заведение (тенант) получает:

- Свою базу 1С для хранения сотрудников и записей.
- Публикацию HTTP-сервиса на Apache.
- Свою карточку в боте MAX — с названием, адресом, телефоном.

Клиенты через бота MAX:

- Выбирают заведение.
- Смотрят свободные слоты.
- Записываются к конкретному сотруднику на конкретное время.

---

## Основной пользовательский сценарий

1. Пользователь пишет боту `/start` в MAX.
2. Бот показывает главное меню.
3. Пользователь нажимает **«🏢 Выбрать заведение»** и выбирает парикмахерскую.
4. Нажимает **«✍️ Записаться»**.
5. Выбирает дату в календаре (кнопками, листает недели стрелками `◀️`/`▶️`).
6. Выбирает сотрудника из списка (кнопками).
7. Выбирает свободное время (кнопками).
8. Вводит имя и телефон.
9. Бот создаёт запись в 1С выбранного заведения.
10. Пользователь получает подтверждение и главное меню.

## Состав и архитектура решения

```
┌─────────────────────────────────────────────────────────┐
│                  MAX Bot (FastAPI)                       │
│  - Приём вебхуков от MAX                                 │
│  - Логика выбора тенанта                                 │
│  - Календарь, inline-меню, кнопки                        │
│  - Логика расчёта свободных слотов                       │
└─────────────┬───────────────────────────────────────────┘
              │
              ├─── SQLite (tenants.db) — список подписчиков
              ├─── Redis — сессии пользователей (TTL 1 час)
              │
              ├─── 1С #1 (booking1) → парикмахерская A
              └─── 1С #2 (booking2) → парикмахерская B
```

**Компоненты проекта:**

| Файл | Назначение |
|---|---|
| `main.py` | FastAPI, приём вебхуков от MAX, вся логика бота, календарь, меню |
| `database.py` | Работа с SQLite: `init_db()`, `get_all_tenants()`, `get_tenant_by_code()` |
| `models.py` | Модель `Tenant` (SQLAlchemy) |
| `Dockerfile` | Сборка образа Python 3.12-slim + сертификаты Минцифры |
| `docker-compose.yml` | Запуск backend + Redis + volume для SQLite |
| `requirements.txt` | Зависимости Python |
| `.env.example` | Пример переменных окружения |
| `.dockerignore` | Исключения для Docker |
| `data/tenants.db` | SQLite (создаётся автоматически при старте) |

## Внешние сервисы и интеграции

### MAX Bot API

- **Endpoint:** `https://platform-api2.max.ru`
- **Назначение:** приём вебхуков от MAX, отправка сообщений пользователям.
- **Сертификат:** требует корневые сертификаты Минцифры (устанавливаются в `Dockerfile`).

### 1С:Предприятие

- **Публикация:** Apache + модуль расширения веб-сервера 1С (`wsap24.so`).
- **HTTP-сервисы:** `getEmployees`, `records`, `createBooking`, `ping`.
- **Базы:** каждая парикмахерская — отдельная база (`BaseMax`, `BaseMax1`).
- **Авторизация:** Basic Auth Apache (`max_service`) + `Usr`/`Pwd` в `default.vrd`.

### Redis

- **Назначение:** хранение сессий пользователей (какой шаг диалога, какой тенант выбран, какие данные введены).
- **TTL:** 1 час (сессии автоматически истекают).
- **Volume:** `redis-data` — данные сохраняются между перезапусками.

### SQLite

- **Назначение:** хранение списка тенантов (подписчиков).
- **Файл:** `/app/data/tenants.db` внутри контейнера, `./data/tenants.db` на сервере.
- **Volume:** `./data:/app/data` — данные сохраняются между перезапусками.

## Работа с данными

### SQLite: таблица `tenants`

| Поле | Тип | Описание |
|---|---|---|
| `id` | INTEGER PK | Автоинкремент |
| `code` | TEXT UNIQUE | Уникальный код тенанта (`barber_main`) |
| `name` | TEXT | Название заведения |
| `type` | TEXT | Тип (`barbershop`) |
| `address` | TEXT | Адрес |
| `phone` | TEXT | Телефон |
| `onec_url` | TEXT | URL HTTP-сервиса 1С |
| `onec_user` | TEXT | Логин 1С |
| `onec_password` | TEXT | Пароль 1С |
| `is_active` | BOOLEAN | Активна ли подписка |
| `subscription_until` | DATETIME | Дата окончания подписки |
| `created_at` | DATETIME | Дата создания |

### Redis: ключи

| Ключ | Значение |
|---|---|
| `state:<user_id>` | JSON с состоянием диалога пользователя |

Пример состояния:

```json
{
  "step": "book_name",
  "tenant_code": "barber_main",
  "date": "2026-09-28",
  "employee_id": "000000001",
  "employee_name": "Иванов Иван",
  "time": "14:00",
  "_updated_at": 1790525000.0
}
```

## Порядок работы с тестовыми данными

### 1. Подготовить две базы 1С

- **`BaseMax`** — первая парикмахерская.
- **`BaseMax1`** — вторая парикмахерская (создаётся через `cp -a` и очищается от старых данных).

В каждой базе:

- Справочник `Сотрудники` с заполненными записями.
- Регистр сведений `Записи` (пустой).
- HTTP-сервис `Макс_Запись` с методами:
  - `ping` (GET)
  - `getEmployees` (POST)
  - `records` (POST, читает `date` и `employee` из query-параметров)
  - `createBooking` (POST, читает JSON из тела)

### 2. Опубликовать базы на Apache

```bash
# Первая база
cd /opt/1cv8/x86_64/8.3.27.2342/
sudo ./webinst -publish -apache24 -wsdir booking -dir /var/www/1c/booking \
  -connstr "File=/var/1c/BaseMax;" -confpath /etc/apache2/apache2.conf

# Вторая база
sudo ./webinst -publish -apache24 -wsdir booking2 -dir /var/www/1c/booking2 \
  -connstr "File=/var/1c/BaseMax1;" -confpath /etc/apache2/apache2.conf

sudo systemctl restart apache2
```

### 3. Проверить, что базы независимы

```bash
curl -u Max:пароль -X POST "http://сервер/booking/hs/booking/getEmployees"
curl -u Max:пароль -X POST "http://сервер/booking2/hs/booking/getEmployees"
```

Сотрудники должны быть **разные**.

### 4. Настроить тенантов

В `database.py` уже прописаны два тестовых тенанта:

```python
t1 = Tenant(
    code="barber_main",
    name="Парикмахерская на Ленина",
    onec_url="http://178.21.11.91/booking/hs/booking",
    ...
)
t2 = Tenant(
    code="barber_center",
    name="Парикмахерская в центре",
    onec_url="http://178.21.11.91/booking2/hs/booking",
    ...
)
```

Если нужны другие адреса — отредактируй перед первым запуском (или очисти `data/tenants.db` и перезапусти).

### 5. Запустить контейнер

```bash
docker compose up -d --build
```

`init_db()` создаст SQLite и добавит тенантов.

## Пошаговый сценарий проверки

### Шаг 1: Проверка backend

```bash
curl http://localhost:8000/health
```

Ожидаемо: `{"backend":"ok","redis":"connected","tenants":[...]}`.

### Шаг 2: Открыть бота в MAX

Найти бота по нику, написать `/start`.

Ожидаемо: приветствие + главное меню (6 кнопок).

### Шаг 3: Выбрать заведение

Нажать **«🏢 Выбрать заведение»** → выбрать **«Парикмахерская на Ленина»**.

Ожидаемо: `✅ Выбрано: Парикмахерская на Ленина` + адрес + меню.

### Шаг 4: Записаться

1. Нажать **«✍️ Записаться»**.
2. Выбрать дату в календаре (например, `28`).
3. Выбрать сотрудника (например, «Иванов Иван»).
4. Выбрать время (например, `14:00`).
5. Ввести имя (например, `Пётр Петров`).
6. Ввести телефон (например, `+79001234567`).

Ожидаемо: `✅ Запись создана!` + меню.

### Шаг 5: Проверить запись в 1С

```bash
curl -u Max:пароль -X POST "http://178.21.11.91/booking/hs/booking/records?date=2026-09-28"
```

Ожидаемо: JSON с записью `Пётр Петров` на `14:00`.

### Шаг 6: Проверить второе заведение

1. Снова **«🏢 Выбрать заведение»** → **«Парикмахерская в центре»**.
2. Повторить запись.

Проверить через:

```bash
curl -u Max:пароль -X POST "http://178.21.11.91/booking2/hs/booking/records?date=2026-09-28"
```

Записи в двух базах должны быть **разные**.

## Известные ограничения

- **Оплата подписки** — не автоматизирована. Тенанты добавляются вручную в SQLite (или через CLI-скрипт).
- **HTTPS** — в текущей версии используется xTunnel для тестирования. Для production нужен Nginx + Let's Encrypt.
- **MAX не поддерживает встроенные платежи** — нужна внешняя платёжная система или ручное подтверждение.
- **Масштабирование** — работает с двумя базами 1С. Для N тенантов потребуется автоматизация публикации баз.
- **`records` в 1С** — параметры передаются в **query-параметрах URL**, даже при POST. Это особенность BSL-метода.
- **`getEmployees` в 1С** — вызывается через **POST**, без тела.

## Порядок остановки и повторного запуска

### Остановить

```bash
docker compose down
```

### Запустить снова (без пересборки)

```bash
docker compose up -d
```

### Полная пересборка (если менялись `.py` или `Dockerfile`)

```bash
docker compose down
docker compose up -d --build
```

### Пересборка без кэша (если что-то странное)

```bash
docker compose down
docker compose build --no-cache
docker compose up -d
```

### Данные сохраняются в

- `./data/tenants.db` — SQLite (volume)
- `redis-data` — Redis (named volume)

После перезапуска все тенанты и сессии на месте.
